# Phase 26 懸念・分析レポート

**日付**: 2026-03-05
**目的**: $100固定資本での収益最大化検討

---

## 500h lookbackの正しい理解

- **ローリングウィンドウ**: 常に「直近500時間」を見る（固定期間待ちではない）
- 毎時1時間ずつスライド
- 取引所が `fetch_funding_rate_history(limit=500)` で過去500h分を一括提供
- → 新通貨追加時に「20日待ち」は発生しない

## 本当のボトルネック

1. **ホワイトリスト13通貨**: 229通貨中13しか候補にならない
2. **スキャン間隔7日**: 週1回しか新通貨を検討しない
3. **スキャン間は盲目**: 7日間ポートフォリオ外の通貨のFR変化を追えない

## 検討した改善案

### A. ホワイトリスト拡張 (13→30)
- **リスク**: ほぼゼロ（流動性フィルタが自動で不適格排除）
- **効果**: 候補数2倍以上
- **結論**: やるべき

### B. スキャン高速化 (7日→3日)
- **リスク**: ゼロ（読み取り専用操作）
- **効果**: チャンス検出2倍速
- **結論**: やるべき

### C. グローバルFRストア (30通貨の常時FR収集)
- **リスク**: ゼロ（データ収集のみ）
- **効果**: 長期的にデータ蓄積、スキャン間のFR変動把握
- **懸念**: 即効性は低い。取引所が過去500h提供するため短期的にはA+Bで十分
- **結論**: やる価値はあるが優先度は A, B より低い

### D. entry_lookback短縮 (500h→168h) ← 却下
- **リスク**: 中。短期スパイクで偽エントリーの可能性
- **効果**: エントリー判定の高速化
- **却下理由**: ユーザー方針「データを減らすな」に反する。過学習防止の精神に反する。

### E. アイドル時適応エントリー ← 却下
- **リスク**: 中〜高。lookbackを動的に変更するのは実質パラメータ追加
- **却下理由**: 0パラメータ原則に反する可能性

## 収益見積もり（正直な数字）

| シナリオ | 現状 | A+B実施後 | A+B+C実施後 |
|---------|------|----------|------------|
| ブル相場 | ~12% | ~14-16% | ~14-16% |
| 普通の相場 | ~8.8% | ~10-12% | ~10-12% |
| ベア相場 | ~3-5% | ~3-5% | ~3-5% |

- ベア相場では30通貨監視しても全部FR負なので改善効果なし
- ブル相場で最も効果大（候補が多いほど最良FR通貨を拾える）
- $100資本での年間差: +$1-4程度

## 「革命」の限界

- FR収穫の年率上限: ~16%（ブル市場最大）
- $100 × 16% = $16/年 = $1.33/月
- 資本に完全に線形 → $1,000なら$160/年、$10,000なら$1,600/年
- コード改善で年率は+1-4%ポイント改善可能だが、生活を変える金額にはならない
