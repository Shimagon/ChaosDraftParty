ユーザーが「これ良い」「OK」「良いね」と明示的に approve した視覚結果（色・材質・シェイプ・プロポーション）を、後続の独立リクエストで自己判断で変えるのは禁止。

**Why:** ユーザー発言（2026-04-23）「さっきのガラスの方が良かった。ちゃんと透明なんだなってわかるし。これは発光してる気がする。勝手に変えるんじゃなくて。先に聞いて欲しい」。直前に amber clear (0.30, 0.22, 0.18, 0.48) を「ガチャカプセル感あっていい」と承認したあと、リファレンス画像（pure clear glass）を見せた時に勝手に pure white に変えてしまい、「発光してる」レベルの劣化に。ユーザーは画像を「参考として見せた」だけで変更指示はしてない。

**How to apply:**
- 「色変えて」「ちょっと違う方向に」等、方向性が曖昧な指示を受けたら **1 回 iterate して approve 取る**。approve 後は勝手に再調整しない。
- ユーザーが**参考画像を示す**のは「参考」であって指示ではない。「これに合わせて変えますか？」と必ず聞く。
- 既に approve 済みの値を変える合理的理由（他のリクエストと矛盾、エラー発生等）がある時だけ、**変更 proposal + why** を先に提示してから実行。
- 特に "色・透明度・形状・比率" の 4 点は承認 snapshot として尊重する。
- 新規 build や大改造時に material を「ついでに」弄らない。明示的に指示された変更だけ適用。

これは「まずは調べろルール」と対。調べた後でも、ユーザーが既に決めた部分を勝手に動かしてはならない。
