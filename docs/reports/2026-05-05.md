## 完了スコープ

### 1. PlayerController v3
- WASD 移動 + Ctrl ダッシュ + Space ジャンプ + Shift しゃがみ
- 移動方向 = camera 相対 (`Vector3.ProjectOnPlane`)
- キャラを進行方向に Slerp 自動回転
- Cinemachine **OrbitalFollow** で自由視点（ThirdPersonFollow は target.rotation 読まないため不適）
- 視点入力は **InputAxisController なしで OrbitalFollow.HorizontalAxis/VerticalAxis に直接書込**
- M2 NetworkBehaviour 化前提の Apply* 関数分離設計
- InputAction は `BuildInputActions` 内で code-defined（asset 不要）、`OnDestroy` で全 Dispose

### 2. EggybotArmLock（新規 component）
**目的**: Run 等の humanoid clip で体軸が前後左右に揺れて Hand_L/R 球が浮く問題を抑える。

設計階層:
1. **Body axis freeze** (`bodyAxisFreeze=1.0`) — Hips/Spine/Chest/UpperChest の **world rotation を root に揃える**
2. **Arm axis freeze** (`armAxisFreeze=0.0`) — 腕は自由 (体軸が固定されてれば腕は安定して振れる)
3. **Hips position lock XZ/Y** — 横ずれ + Y bob 完全消失
4. **Local lock 個別 sliders** (Spine/Chest/Shoulder/UpperArm/LowerArm/Hand) — 細部チューニング用
5. `restRots` の取得は **Start** で（Awake は bone reference のみ、humanoid muscle 正規化が完了するのを待つ）

これで **Idle / Walking / Run / Jump / 将来のスキル系 anim 全部に共通対応**。

### 3. Animator Controller 拡張

  - threshold 8 → Run clip

- `JumpHash` キャッシュで毎フレ StringToHash 回避

### 4. Mixamo fbx import 整合

### 5. Cinemachine 床貫通防止 — 動的 minPitch clamp
3 段重ねを試した結果、**入力側で hard clamp する単一方式**に収束:

```csharp
float radius = Mathf.Max(orbital.Radius, 0.1f);
float targetY = cinemachineCamera.LookAt.position.y;
float sinMin = Mathf.Clamp((cameraMinWorldY - targetY) / radius, -1f, 1f);
float dynamicMinPitch = Mathf.Asin(sinMin) * Mathf.Rad2Deg;
v.Value = Mathf.Clamp(v.Value - lookDelta.y * pitchSensitivity, Max(Range.x, dynamicMinPitch), Range.y);
```

Cinemachine 公式 `CinemachineGroundClamp` extension（自作）と `CinemachineDeoccluder.MinDist` を**併用すると 3 つが競合して「ガクッ」と跳ねる**ため、入力側で 1 箇所だけ防ぐのが最も滑らか。

### 6. カメラ業界標準値の導入
NotebookLM の代わりに 3 並列 web research → consensus:
- LookAt 高さ = キャラ身長の 70% (CameraTarget local Y=0.5、世界 Y=0.7 = 胸)
- Radius = 5m (cameraDashRadius=6m)
- VerticalAxis Center = 15° (やや見下ろし)
- VerticalAxis Range = (-30°, 60°) (動的 clamp が主役、Range は安全網)
- Deoccluder 装備 (壁裏遮蔽防止、MinDist=1.5 で顔崩れ防止)

## 試行錯誤記録（教訓）

### 失敗 1: 新クリップの import 設定が Walking と違って Hips Y +0.7m 浮上
- 取り込み直後の Idle/Run/Jump で「手が頭の横、足が宙に浮く」状態
- 並列 agent で実測: Hips Y = Walking 0.41m / Idle 1.12m
- 真因: **sourceAvatar が EggybotV16Avatar、keepOriginalPositionY=true、lockRootHeightY=false** で Mixamo Y Bot 等身大の Hips Y がそのまま baked
- Walking と完全一致させて解決

### 失敗 2: 体軸を freeze したら腕も止まった
- `upperBodyAxisFreeze=1.0` で全 12 bone (Hips〜手) に lock 適用 → 腕も完全停止
- 修正: **body と arm を別 slider に分離**。体軸固定でも腕は自由に振れる
- 結論: **Hips/Spine/Chest world rotation を root に揃えるだけで「軸固定」は実現**、腕 bone の localRotation は anim 任せで OK

### 失敗 3: 床貫通の 3 段重ね clamp 競合
- VerticalAxis Range（hard limit）+ CinemachineDeoccluder MinDist（pull forward）+ CinemachineGroundClamp extension（Y clamp）の 3 つを同時に効かせたら、それぞれが別の優先度で発火して「ガクッ」と跳ねる
- 真因: 3 つとも事後補正で位置を書き換える → 順番依存
- 解決: **入力側で動的 minPitch を計算して hard clamp**。事後補正全廃、smooth に「壁にコツン」で止まる

### 失敗 4: orbital.VerticalAxis.Value を code 直書きで Range が効かない
- Cinemachine 3.x の `InputAxis.Range` は Inspector slider 用、code 経由の代入では auto-clamp されない
- 修正: ApplyLook 内で `Mathf.Clamp(v.Value - delta, Range.x, Range.y)` を明示
- これだけで床貫通の主原因が解消

### 失敗 5: EggybotArmLock の Awake で restRots 取得が早すぎ
- humanoid Avatar の muscle 正規化が Awake 完了時点で終わってる保証なし
- code-reviser が指摘 → **Awake で bone reference のみ、Start で restRots 記録**に分離
- `LateUpdate` は `if (!initialized) return;` でガード済なので 1 フレーム遅延は無害

### 失敗 6: Range -10° は radius 5 では床ぎりぎり
- minPitch を実測: target Y=0.7, radius=5 で **-4.59°** が床に触れる境界
- Range を -5° にしても camera Y=0.264m で MinHeight=0.3m を割り込む → GroundClamp 発火 → ガクッ
- 動的計算で常に正確な境界を出すのが正解
