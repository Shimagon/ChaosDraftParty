### 真犯人 (5 周目で見落としてた構造的バグ)

```csharp
// PlayerController.cs (バグ)
if (dashEffect != null) { dashEffect.OnDashStart(); }
//                ↑ enabled チェックなし

// EggybotDashEffect.OnDashStart()
_dipImpulseSource.GenerateImpulseWithVelocity((0, -0.5, 0));  // ★ camera Y impulse
_targetFov = _dashFov;                                          // ★ FOV punch
_speedLines.Play();
```

`dashEffect.enabled = false` にしても、**外部 (PlayerController) から `OnDashStart()` 呼ばれる経路は阻止されてなかった**。
Unity の `enabled` は **Update / OnEnable / OnDisable サイクルのみ制御**、public method の外部呼出は阻止しない。

### 修正

```csharp
public void OnDashStart() {
    if (!enabled) return;  // ← defensive guard 追加
    _targetFov = _dashFov;
    if (_dipImpulseSource != null) _dipImpulseSource.GenerateImpulseWithVelocity(_dipImpulseVelocity);
    if (_speedLines != null && !_speedLines.isPlaying) _speedLines.Play();
}
```

`EggybotMovementVFX.PlayLanding / OnDashStateChanged` にも同パターン適用 (将来の事故防止)。

### 学び

- **`enabled = false` ≠ component 完全停止**。public method の外部呼出は素通り。
- **disable で機能停止を狙う component は defensive guard 必須**。
- 「何回 disable しても直らない時は外部呼出経路を疑う」が今後の defacto。
- 並列 agent 3 個 + Cinemachine 構成解析 + Animator 解析を **5 周回した結果**、Agent が「PlayerController から OnDashStart 呼ばれる」を指摘してようやく気付いた。
- **真因到達まで User フィードバック 3 回必要だった** = 浅い修正で迷走したコスト大。
